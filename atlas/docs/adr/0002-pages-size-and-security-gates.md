# Pages artifact size and dependency gates

Date: 2026-10-25. Status: accepted for the current review pass.

The October 14 Pages artifact occupies 984,537,538 uncompressed bytes. It is below the [published 1 GB site limit](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits), but leaves little room for further chapters. A sampled section contains 282,342 bytes of contents-tree HTML, much of it for collapsed branches of other chapters. The tree is repeated across thousands of static pages.

Keep the chapter links and the active chapter's full subtree in the server-rendered page. Load other written chapters' children when the reader expands them. Preserve native chapter navigation if JavaScript or a branch request fails, and validate deferred payloads before creating DOM nodes. This preserves the complete manuscript and current-page navigation while avoiding repeated inactive subtrees. Measure the final artifact after base-path rewriting; do not infer savings from the sample alone.

The deployment workflow now rejects an empty artifact or one above **900,000,000 uncompressed bytes**. This is a project growth budget, with 100 MB below the hosting limit; it is not a performance or comprehension score. The gate counts all files, including fonts, scripts, JSON and images, and rejects symlinks/special entries so that its counting boundary is explicit. No content is truncated to satisfy this budget.

The existing calculator chunk also contains the build-time ELK graph-layout implementation (1,437,660 raw bytes in the October 14 build). Its sensitivity helper imported `sliderModel` from the visual package root, which re-exports layout and imports the ELK module. Expose `@atlas/visual/math` as a public, browser-safe entry and use it there. Lint rejects the build-time package root in browser controllers/islands. Check the final built chunk before reporting its size reduction; the change does not alter the calculator's formulas or use the browser to recompute graph layout.

The refreshed dependency audit also identifies issues absent from the prior review snapshot. Patch Zod to 4.6.7 in each declaring workspace, and resolve compatible transitive patches for Vite, Undici and fast-uri in the lockfile. The [Zod advisory](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5), [Undici advisory](https://github.com/nodejs/undici/security/advisories/GHSA-xjj6-f33q-929c) and [Vite advisory](https://github.com/vitejs/vite/security/advisories/GHSA-rq7h-c2jc-7f22) delimit the affected behavior. Keep the existing supported Node 24.12 runtime; a lint-plugin major migration requiring a newer runtime is outside these targeted patches. Audit both production and development dependencies at the high-severity threshold before publication.

Two low audit entries remain from micromark-extension-math 3.1.0 and its transitive KaTeX 0.16.47. The compiler imports that extension's tokenizer; it renders equations with its direct KaTeX 0.18.7 dependency. The extension's optional HTML renderer is not called by Atlas. The [KaTeX advisory](https://github.com/KaTeX/KaTeX/security/advisories/GHSA-238p-pmpm-9mq7) requires pre-existing prototype pollution or attacker control of renderer-option prototypes. The current source-controlled, build-time input boundary limits reachability, but does not prove that the dependency is generally safe. Do not route untrusted runtime math through the old transitive renderer. Revisit by **2026-11-24**, or immediately if its renderer becomes reachable or an upstream compatible patch is released. A dependency override that did not change the resolved nested package was removed rather than presented as a fix.

Validation requires a clean lockfile installation, formatting/lint/type checks, unit tests, manuscript compilation, browser tests, a Pages-prefixed static build, link/fragment checks, the size gate, and a live smoke check after deployment. Regression cases cover deferred-tree interaction and failure recovery, search loading/closing, and the size boundary. Passing these checks does not establish field performance, full accessibility certification, scientific replication or a numerical editorial rating.
