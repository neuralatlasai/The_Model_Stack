# Top 100 evaluation ecosystem — 2026 priority order (source list, verbatim)

Provided for The Model Stack on 2026-09-25. Ranking, types, and rationales are the list author's editorial judgement; bracketed labels cite the sources listed at the end.

| Rank | Evaluation system | Type | Why it is high in the order |
|---:|---|---|---|
| **1** | **Artificial Analysis** | Independent dashboard + benchmark suite | Probably the strongest single public model-comparison surface today because it independently runs models and combines intelligence with price, latency and throughput. Its current Intelligence Index uses ten evaluations spanning agents, coding, science and general capability. ([Artificial Analysis][1]) |
| **2** | **Epoch AI Capabilities & Benchmarking / ECI** | Independent research database + composite index | Exceptionally strong research-grade longitudinal capability tracking. It currently tracks hundreds of models and dozens of benchmarks and exposes methodology/data rather than only a leaderboard. ([Epoch AI][2]) |
| **3** | **Arena.ai / LM Arena** | Human-preference evaluation platform | Best large-scale real-user preference signal. It measures utility that static QA benchmarks miss through anonymous pairwise human judgments. LMArena rebranded to Arena in January 2026. ([Arena AI][3]) |
| **4** | **METR** | Frontier autonomy/risk evaluation research | Critical for long-horizon autonomous capability, human-calibrated task horizons and AI-R&D evaluation. METR itself warns that time-horizon estimates have large uncertainty and are approaching saturation—exactly the methodological transparency a serious evaluation program should provide. ([METR][4]) |
| **5** | **Mercor Research / APEX** | Expert professional benchmark platform | One of the strongest directions in 2026: economically valuable real work rather than academic QA. APEX now spans professional services, long-horizon agents, accounting and software engineering. ([Mercor][5]) |
| **6** | **Scale SEAL Leaderboards** | Private expert-evaluated leaderboards | Important because test data are private, domain experts grade outputs, and contamination/gaming resistance is explicitly part of the design. ([Scale AI][6]) |
| **7** | **SWE-bench** | Software-engineering benchmark ecosystem | Still one of the canonical real-repository agent/coding measures. Actual GitHub issue resolution is significantly more informative than function-generation benchmarks. |
| **8** | **ARC Prize / ARC-AGI** | Abstract reasoning leaderboard | High-value signal for abstraction/generalization rather than memorized knowledge. Maintains explicit verification policies and cost/task reporting. ([ARC Prize][7]) |
| **9** | **Terminal-Bench + Harbor** | Agent benchmark + execution harness | One of the most consequential 2026 agent evaluations: real terminal environments, difficult evolving tasks, executable verification and standardized Harbor execution. ([GitHub][8]) |
| **10** | **Inspect AI — UK AISI** | Evaluation framework | The strongest open-source general frontier-evaluation framework in my ordering: datasets, agents, tools, scorers, sandboxes, MCP, external agents and 200+ ready-to-run evaluations. ([Inspect][9]) |
| **11** | **LiveBench** | Continuously refreshed benchmark | Designed explicitly against contamination, with new questions introduced over time rather than freezing a static benchmark forever. ([GitHub][10]) |
| **12** | **Berkeley Function Calling Leaderboard — BFCL** | Tool-use / agent leaderboard | Tool calling has become core agent infrastructure. BFCL V4 moves beyond trivial function selection toward multi-turn and agentic evaluation. ([Gorilla][11]) |
| **13** | **τ³-bench** | Conversational tool-agent benchmark | Evaluates policy following, user interaction and tool execution under dynamic environments; materially closer to production agents than static QA. The original τ-bench repository now explicitly points users toward τ³. ([GitHub][12]) |
| **14** | **Stanford HELM** | Holistic benchmark framework | Strong methodology, standardized scenarios and broad evaluation philosophy. Especially useful where transparency across metrics matters more than a single number. |
| **15** | **OpenCompass** | Evaluation platform/harness | Major open evaluation stack supporting 100+ datasets, proprietary/open models and increasingly multimodal evaluation. Active 2026 development matters here. ([GitHub][13]) |
| **16** | **OpenAI Evals API / Graders** | Evaluation service + SDK | Important for production evaluation pipelines, model graders and application-specific eval sets rather than public leaderboard comparison. |
| **17** | **OpenAI Evals OSS** | Open-source evaluation registry | Mature reference architecture for defining model/system evals and private/custom eval datasets. ([GitHub][14]) |
| **18** | **EleutherAI lm-evaluation-harness** | General evaluation harness | Still foundational infrastructure. It implements 60+ standard benchmarks, numerous backends and underpins major open-model evaluation workflows. It remains actively maintained in 2026. ([GitHub][15]) |
| **19** | **FrontierMath** | Frontier mathematics benchmark family | Strong because the problems are deliberately unpublished/extremely difficult; newer variants include research-level and open mathematical problems. ([Epoch AI][16]) |
| **20** | **LiveCodeBench** | Continually refreshed coding benchmark | Better contamination profile than static coding datasets because it continuously draws from recently released competitive-programming problems. ([GitHub][17]) |
| 21 | Humanity's Last Exam | Frontier general reasoning | Extremely difficult multi-domain expert knowledge/reasoning; useful while frontier separation remains substantial. |
| 22 | GDPval | Economically valuable work | Real occupational deliverables rather than exam-style QA; covers economically relevant tasks across occupations. ([OpenAI][18]) |
| 23 | APEX-Agents | Long-horizon professional agents | Multi-hour professional tasks across files, communications and productivity applications. Updated to 1.1 in September 2026. ([Mercor][19]) |
| 24 | APEX-SWE | Professional software engineering | Focuses on economically valuable integration and observability engineering rather than toy coding. ([Mercor][20]) |
| 25 | OSWorld 2.0 | Computer-use agents | Long-horizon GUI/computer interaction in real operating-system environments. OSWorld 2.0/2.1 is the current branch in 2026. ([OSWorld][21]) |
| 26 | RE-Bench | AI-R&D agents | Measures AI agents against human experts on research-engineering tasks; valuable for autonomous AI-R&D capability. ([GitHub][22]) |
| 27 | BrowseComp | Web-research agents | Measures persistent, strategic search for difficult-to-find facts; designed around easy verification but difficult discovery. ([OpenAI][23]) |
| 28 | DeepResearchBench II | Deep-research agents | Long-form web research, information recall, analysis and presentation. Current professional research-agent signal. ([Mercor][20]) |
| 29 | TheAgentCompany | Digital-work agents | Simulated software-company tasks involving browsing, coding, communication and work applications. ([GitHub][24]) |
| 30 | GAIA | General assistants | Multi-step general-agent benchmark with tools/files and private test answers; still actively maintained. ([Hugging Face][25]) |
| 31 | SWE-Lancer | Economic coding | Real freelance engineering tasks linked to actual monetary value and end-to-end verification. ([OpenAI][26]) |
| 32 | Aider Polyglot | Code editing | Particularly useful for realistic edit-based coding rather than isolated function generation. ([GitHub][27]) |
| 33 | SciCode | Scientific coding | Research-derived coding problems across physics, biology, chemistry, mathematics and materials science. ([GitHub][28]) |
| 34 | AgentDojo | Agent security | Stateful agent benchmark combining legitimate task utility with prompt-injection attack success. ([GitHub][29]) |
| 35 | WebArena | Web agents | Interactive web environments and execution-based success. |
| 36 | BrowserGym | Browser-agent infrastructure | Useful common environment/harness for browser-agent evaluation. |
| 37 | VisualWebArena | Multimodal web agents | Adds visual web understanding to browser task execution. |
| 38 | WorkArena | Enterprise/browser agents | Work-oriented web application tasks; useful for enterprise agent evaluation. |
| 39 | τ^τ-bench / Hyper-τ | Agent construction | Tests an outer coding agent constructing a functioning customer-service agent, then evaluates it through τ-style interactions. ([GitHub][30]) |
| 40 | Remote Labor Index | Economic autonomy | Measures agent ability against remote-work tasks; included in Epoch's current capability benchmark ecosystem. ([Epoch AI][31]) |
| 41 | APEX-1 | Professional cognition | High-value banking, consulting, law and medicine deliverables. |
| 42 | APEX-Accounting | Professional accounting agents | Real reconciliation, statements, audit and tax workflows. ([Mercor][20]) |
| 43 | ACE / AI Consumer Index | Consumer tasks | Evaluates realistic shopping, food, DIY and gaming tasks rather than academic questions. ([Mercor][32]) |
| 44 | SimpleQA Verified | Factuality | High-quality verified factual knowledge benchmark; useful as a clean factual layer rather than a holistic intelligence metric. |
| 45 | MirrorCode | Long-horizon coding | Reimplementation of entire software programs rather than isolated functions; part of Epoch's current frontier suite. ([Epoch AI][33]) |
| 46 | DeepSWE v1.1 | Software agents | Stronger emphasis on repository-level software agent performance. |
| 47 | FrontierCode | Frontier coding | Hard coding/agent capability signal included in contemporary capability indices. |
| 48 | ProofBench | Formal reasoning | Important for verifiable proof/reasoning capability. |
| 49 | ExploitBench | Cyber agents | Realistic exploitation/security capability evaluation. |
| 50 | PostTrainBench v1.1 | Post-training | Measures capabilities associated with post-training workflows. |
| 51 | AgentCompass | Agent evaluation infrastructure | Extensible OpenCompass-family infrastructure specifically aimed at LLM/VLM agents; active in 2026. ([GitHub][34]) |
| 52 | LMMs-Eval | Multimodal harness | Unified text/image/video/audio evaluation with 100+ tasks. ([GitHub][35]) |
| 53 | VLMEvalKit | Multimodal harness | One-command VLM benchmarking and broad model/dataset support; increasingly integrated into OpenCompass. ([GitHub][36]) |
| 54 | OpenVLM Leaderboard | Multimodal leaderboard | Useful common leaderboard around standardized VLM evaluations. |
| 55 | MMMU-Pro | Multimodal reasoning | Removes many text-only shortcuts and introduces harder visual reasoning conditions. ([GitHub][37]) |
| 56 | Video-MME | Video understanding | Broad video understanding evaluation and increasingly treated as an industry-standard multimodal test. ([GitHub][38]) |
| 57 | MME-RealWorld | High-resolution multimodal | Stronger emphasis on difficult real-world high-resolution visual scenarios. |
| 58 | MMStar | Vision-indispensable reasoning | Explicitly filters tasks where text alone can solve the problem and studies multimodal leakage. ([GitHub][39]) |
| 59 | OCRBench | Document/OCR multimodal | Important for OCR-centric VLM and document intelligence evaluation. |
| 60 | LongBench v2 | Long context | Contexts from 8K to extremely long inputs, emphasizing deeper understanding rather than needle retrieval. ([GitHub][40]) |
| 61 | RULER | Long context | Measures effective rather than advertised context length across configurable long-context tasks. ([GitHub][41]) |
| 62 | InfiniteBench | Extreme context | Stress test for very-long-context model behavior. |
| 63 | HELM Safety | Safety benchmark suite | Standardized public safety evaluation across multiple risk categories. ([Stanford CRFM][42]) |
| 64 | HarmBench | Safety/red teaming | Canonical harmful-behavior and jailbreak evaluation suite. |
| 65 | JailbreakBench | Robustness benchmark | Open benchmark for attacks, defenses and jailbreak artifacts with an official leaderboard. ([GitHub][43]) |
| 66 | StrongREJECT | Refusal robustness | Better than naive refusal scoring for measuring harmful-request compliance. |
| 67 | Agent Security Bench | Agent safety | Security evaluation specifically for tool-using autonomous agents. |
| 68 | CyberSecEval | Cybersecurity | Security/cyber capability and risk evaluation. |
| 69 | ToolSandbox | Stateful tool use | Tests stateful tool interactions where tool-call sequence and world state matter. |
| 70 | NVIDIA garak | Red-team framework | Mature vulnerability scanner covering jailbreaks, injection, leakage, hallucination and toxicity. ([Garak][44]) |
| 71 | Microsoft PyRIT | Red-team framework | Highly relevant enterprise adversarial-testing framework with reusable attack scenarios. ([Microsoft GitHub][45]) |
| 72 | Inspect Evals Register | Benchmark registry | Important bridge between standardized benchmark definitions and the Inspect execution stack. ([GitHub][46]) |
| 73 | DeepEval | Application/agent eval framework | Excellent pytest-native unit/regression evaluation; now supports end-to-end, component and trajectory evaluation with 50+ metrics. ([DeepEval][47]) |
| 74 | Confident AI | Managed evaluation platform | Managed collaboration/observability layer around DeepEval; useful when local eval code has to become a team/production workflow. ([DeepEval][48]) |
| 75 | Ragas | RAG evaluation framework | Still one of the canonical RAG-specific evaluation toolkits; evolving toward experiment-oriented APIs. ([Ragas][49]) |
| 76 | Promptfoo | Eval + red-team framework | Strong CI-native prompt/model/agent regression framework with deterministic assertions and red-team capabilities. ([Promptfoo][50]) |
| 77 | LangSmith | Application evaluation platform | Strong offline benchmarking, regression, backtesting, LLM judges and online evaluation integrated with tracing. ([Docs by LangChain][51]) |
| 78 | Braintrust | Evaluation/observability platform | Strong experiment-driven production evaluation workflow. |
| 79 | Arize Phoenix | Open-source observability/evals | Strong traces + evaluation combination, especially RAG/agent debugging. |
| 80 | Weights & Biases Weave | Evaluation/observability | Natural choice for teams already using W&B experiments/artifacts. |
| 81 | MLflow GenAI Evaluation | OSS lifecycle/eval framework | Serious 2026 option: datasets, judges, human feedback, traces, production monitoring and `mlflow.genai.evaluate`. ([MLflow AI Platform][52]) |
| 82 | Langfuse | Open-source eval/observability | Particularly good evaluation loop from production traces → datasets → experiments → deployment monitoring. ([Langfuse][53]) |
| 83 | TruLens | Evaluation framework | Mature feedback/evaluator model and strong RAG/agent instrumentation. ([TruLens][54]) |
| 84 | Opik | OSS evaluation/observability | Test suites, datasets, quantitative metrics and agent tracing. ([Comet][55]) |
| 85 | Patronus AI | Evaluation platform | Specialized evaluator API, experiments, production scoring and hallucination/safety evaluation. ([Patronus Docs][56]) |
| 86 | Giskard | Evaluation/red-team platform | Strong behavioral testing, LLM judges, vulnerability scanning and CI/CD. ([Giskard Documentation][57]) |
| 87 | Galileo | Evaluation/observability | Production-focused model/application evaluation and monitoring. |
| 88 | HoneyHive | Evaluation platform | Experiment and trace-based LLM application evaluation. |
| 89 | Parea | Evaluation platform | Dataset/evaluator/experiment workflow for model and prompt iteration. |
| 90 | Vellum | Evaluation/workflow platform | Good application-level comparison when evals need to sit next to orchestration/workflow tooling. |
| 91 | Maxim AI | Evaluation platform | Broader production experimentation/evaluation environment. |
| 92 | Evidently AI | Evaluation/monitoring | Useful where LLM quality evaluation must live beside conventional ML/data monitoring. |
| 93 | Azure AI Evaluation SDK | Cloud SDK | Strong enterprise evaluator library covering groundedness, relevance, safety, retrieval and agent-specific tool-call/task-adherence evaluation. ([Microsoft Learn][58]) |
| 94 | Vertex AI Gen AI Evaluation | Cloud evaluation service | Managed Google Cloud model/application evaluation. ([Google Cloud Documentation][59]) |
| 95 | Amazon Bedrock Evaluations | Cloud evaluation service | Supports automated, LLM-judge, human and RAG evaluations, including non-Bedrock sources. ([AWS Documentation][60]) |
| 96 | EvalScope | Evaluation + performance framework | Useful one-stop ModelScope framework spanning LLM/VLM capability eval and inference-performance benchmarking. ([GitHub][61]) |
| 97 | WeirdML v2 | Frontier niche benchmark | Current hard benchmark included in Epoch's capability-index input set. ([Epoch AI][31]) |
| 98 | Surface Evolver Bench | Scientific/agent benchmark | Specialized difficult scientific/computational task signal used in current frontier composite evaluation. ([Epoch AI][31]) |
| 99 | Earthborne Rangers / EBR-bench | Learning/adaptation benchmark | Tests whether systems improve through repeated interaction rather than measuring only static knowledge. ([Epoch AI][33]) |
| 100 | Mystery Game Puzzles | Hidden-rule reasoning | Useful niche evaluation of inference under deliberately undisclosed game structure; tracked by Epoch. ([Epoch AI][33]) |
