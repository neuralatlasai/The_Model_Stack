# Chapter 42 verification

## Artifact specification

[DERIVED] The plan's artifact is an inference memory/latency estimator validated against measurements. This edition supplies its scientific specification and analytical instruments, not a claim that the estimator has been implemented or measured. A future implementation must retain the following records together:

| Proposed artifact | Required fields |
|---|---|
| identity manifest | model/config/tokenizer/template hashes, adapter identity, source/runtime commit, container, driver, hardware/topology, backend, graph mode, dtype, decoding/stop policy |
| tensor ledger | logical object, shape, dtype, element count, scale/zero metadata, packing/padding, physical allocation ID, aliases, owner rank/cache group, lifecycle class |
| state placement | attention/recurrent/latent tensor contracts, retained lengths, head/layer ownership, duplication factors, page sizes, physical strides, block generations |
| allocation trace | allocate/free and live intervals, logical occupied pages, pool reserve, graph pools, workspace/communication buffers, synchronized tensor/reserved/process counters |
| phase trace | ingress, encode, admit, compute, select, publish/cancel times; processed/selected/visible token counters; per-iteration prompt/decode rows and attended context |
| workload ledger | joint prompt/output lengths, content/template identity, arrival times, prefix sharing, sampling settings, cancellations, retries and source split membership |
| calibrated model | exact features, units, fitting constraints, train/holdout split, validity domain, lower bounds, parameter uncertainty, excluded configurations |
| residual report | allocation residual by category, per-phase/prompt/output/batch/load timing error, mean/tail error separately, failure events and domain violations |
| recovery ledger | timeout, cancellation, partial write, offload miss/corruption, preemption/recompute, reference/completion transitions and committed prefix |
| evidence register | primary keys/locators, inspection revision/date, reported versus book-derived claims, unresolved gaps and review consequences |

## Verification task

### Experiment 42.1 — Reconcile state and conditional execution

**Hypothesis.** [ASSUMED] Under a pinned conventional full-attention implementation, Eq.42.3 predicts logical KV tensor bytes exactly; measured physical allocation differs by identifiable pages, metadata, reserve and execution buffers. A calibrated iteration model predicts held-out means within the chosen domain and rejects unsupported configurations.

**Setup.** [ASSUMED] Select one openly inspectable decoder with a documented state layout and two supported cache dtypes. Pin all identities before running. Establish a native exact full-history baseline, then isolate paging, warm-prefix reuse and cache dtype one at a time. Use the same tokenizer/template, stop policy, backend and precision where the intervention permits; record any unavoidable changed operator.

**Independent variables.** [ASSUMED] Prompt length $\{128,512,2048,8192\}$ and output length $\{1,32,256,1024\}$ vary independently where supported; active batch $\{1,4,8\}$; cold versus exact shared prefix; supported state dtype. These are experimental inputs, not reported facts. Sensitivity: unsupported lengths are rejected, not truncated silently; page-boundary neighbors are added to expose rounding.

**Controlled variables.** [ASSUMED] Same model/executable identity, content population, seed policy, decoding selection, hardware, kernel flags, warmup/capture procedure and measurement boundaries. Separate initialization, graph capture, steady prefill and decode. Repeat with stable independent request arrivals only after isolated iteration measurements.

**Dataset/workload.** [ASSUMED] Versioned natural-text prompts with no model-training claims, plus synthetic token arrays for pure memory/shape checks. Retain exact encoded lengths. Hold out entire length/batch combinations, and later a distinct arrival trace, from calibration. A shared-prefix test changes one conditioning component at a time: tokens, adapter, positions, modality identity, namespace/salt.

**Hardware.** [ASSUMED] One available supported accelerator for the primary study; then a supported multi-rank mesh if available. Record exact device memory, topology, runtime and clocks from first-party/device observations. No named accelerator performance is assumed by this proposal.

**Metrics.** [ASSUMED] Logical/physical/reserved/process bytes; page-tail and alias counts; peak liveness; HBM/link traffic when measurable; per-iteration elapsed time; client-visible TTFT, TPOT, ITL and E2E under the shared definitions; separate p50/p95/p99 and goodput. Record token-level traces, task-quality outcomes and power only when the measurement boundary is available.

**Baselines.** [ASSUMED] Native full-history state; cold state; no sharing; one replica; directly measured isolated iteration surfaces. Compare a weight-only predictor, ideal KV predictor, full liveness ledger and calibrated predictor as different model classes.

**Expected result.** [ASSUMED] Logical bytes match the declared tensor shapes. Physical residuals are explainable without double counting. Warm reuse preserves the declared numerical/output contract. A held-out mean predictor is useful only inside its recorded domain; tail accuracy is evaluated independently.

**Ablation.** [ASSUMED] Toggle one mechanism at a time. Repeat with graph capture disabled, with page-boundary lengths, with a shared full block versus a shared partial tail and with independent prompt/output variation. A rejected configuration remains in the report. Do not compare task speed until output/selection differences are explained.

**Interpretation.** [DERIVED] A logical-byte mismatch rejects representation accounting. A residual above tolerance rejects allocation reconciliation. Invalid warm-state reuse rejects key/lifetime correctness. A fit below a valid physical lower bound rejects its units/counts. Holdout failure rejects the prediction domain; it does not refute the exact storage identity.

**Threats to validity.** [DERIVED] Allocator sampling can miss peaks; synchronization can perturb timing; graph pools can persist between cases; generated output length may differ when EOS is allowed; request residence biases in-flight statistics; background activity changes effective bandwidth. Block identity can be wrong despite a digest match if conditioning is omitted. A seed cannot guarantee cross-version equivalence.

### Experiment 42.2 — Reduction and recovery under future-query shifts

**Hypothesis.** [ASSUMED] Numerical, retention and location changes have distinguishable quality/resource/failure effects under a fixed native checkpoint.

**Setup.** [ASSUMED] Apply only supported policies: native full history, a declared quantized cache, a declared retained-token budget and exact prefix offload/recompute. Preserve identical native token sequences for forced-token state comparisons before testing free generation.

**Independent variables.** [ASSUMED] Bit width or scale granularity, residual length, retained-token budget, delayed-query distance, prefix reuse interval and effective tier latency. Sensitivity: vary each around its chosen setting and include full native state as the reference.

**Controlled variables.** [ASSUMED] Exact checkpoint, prompt content, task evaluator, selection rule, generation budget and hardware. Keep the task metric separate from reconstruction/logit error.

**Dataset/workload.** [ASSUMED] Independent generation and delayed-query retrieval tasks whose needed facts occur both inside and outside the retained region. No invented universal error threshold is assumed. Use the source paper's original evaluation recipe only when its artifacts can be pinned.

**Hardware.** [ASSUMED] The supported device/tier used in Experiment42.1, with measured transfer and capacity boundaries.

**Metrics.** [ASSUMED] Actual cache and transient peak bytes, state/logit differences, accepted task rate, TTFT/ITL, bytes restored/recomputed, integrity failures and recovery time. Energy/cost remain unresolved unless measured.

**Baselines.** [ASSUMED] Native state; recompute from the complete exact token prefix; rolling-window recompute versus retained rolling state as separate conditions.

**Expected result.** [ASSUMED] A capacity improvement is reported only with its approximation or recovery cost. Exact tier misses recover correctly or fail explicitly. Retained-context streaming is never scored as retaining discarded facts.

**Ablation.** [ASSUMED] Change scale grouping/residual, sink region or importance scorer independently where supported. Inject cancellation during transfer/write and stale-identity records. No production or confidential workload is needed.

**Interpretation.** [DERIVED] A local compression-error improvement without task improvement supports only the local metric. A reduction that increases restoration stalls can still save memory but fails a latency criterion. A corrupt/incomplete tier hit accepted as valid state rejects correctness.

**Threats to validity.** [DERIVED] Tasks can overrepresent easy recent facts; perturbing decode can change later state trajectories; benchmark scores can hide rare failures. Backend changes can confound numerical and execution gains. Source-reported protocols do not supply independent replication.

## Acceptance criteria

[ASSUMED] Proposed engineering thresholds are chosen before measurement and are not manuscript results:

- Exact logical element/byte counts must agree with the inspected tensor inventory; integer mismatches have zero tolerance.
- Physical ledger residual must be at most the larger of one physical page or 1% of process bytes after every known category is assigned. Sensitivity: report conclusions at 0.5%,1% and2%; passing a threshold does not explain an unidentified object.
- No tested unauthorized or incompatible reuse may be accepted; no in-flight block may be reclaimed. Tested logits must meet a dtype/backend-specific tolerance justified against a native reference before tests begin.
- At least three independent repetitions per condition; retain all samples and report dispersion. Increase repetitions if confidence intervals cannot distinguish the declared error tolerance.
- Mean conditional iteration prediction targets 10% median relative error and 20% maximum error over the declared holdout grid. These are proposed acceptance choices, not source results. A systematic failed region is removed from the validated domain and reported.
- No p95/p99 accuracy claim without a separately validated distributional/trace test and enough samples for the claimed quantile.
- Recovery either returns a state matching the declared native/approximate contract or a named failure; partially written/incorrectly identified state is never published.
- Quality loss, energy and monetary thresholds must be specified by the intended task/deployment before any optimization is selected. They are not guessed in this chapter.

## What this edition did not do

[DERIVED] Both experiments are unexecuted proposals. No GPU allocation, benchmark, model-quality, energy, monetary, load-test or fault-injection measurements were produced. Source code was not executed or commit-audited. Figures execute analytical formulas with explicit illustrative inputs; that is not empirical validation of an inference engine. Scientific reviewed status remains blocked by the applicable implementation, numerical, experimental, systems and operational gates.
