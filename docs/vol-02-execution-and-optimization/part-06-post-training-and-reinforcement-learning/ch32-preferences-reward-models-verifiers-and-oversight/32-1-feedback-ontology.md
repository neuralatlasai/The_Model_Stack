# 32.1 — Feedback ontology

## Scope

[DERIVED] Specify what a feedback channel observes, what proposition its output supports, and what downstream transformation turns that output into a training signal. This section owns human preference, AI feedback, deterministic verification, execution outcomes, process labels, and environment returns. Success is a typed, versioned feedback record whose evidential meaning survives batching, aggregation and optimization. The reward model is an estimator of a declared target; the verifier is a decision procedure over a declared domain; oversight is the organization of evidence and authority. Neither the scalar interface nor the identity of the producer makes these objects interchangeable.

## Why this exists

[DERIVED] Reducing all feedback to a float destroys information needed to interpret that float. A preference comparison conditions on a rubric and two candidates. A test result conditions on executable artifacts, fixtures and a harness. A process annotation conditions on a prefix and a definition of permissible progress. An environment return conditions on a trajectory and termination semantics. Mixing these records without carrying their conditioning variables creates an objective whose numerical value is defined but whose meaning changes between examples.

[PAPER-REPORTED] IRPM trains a pointwise generative evaluator from paired human preferences, whereas VPR obtains turn-level signals from algorithmic oracles. Their supervision sources and inference procedures differ even when both ultimately produce scalar rewards. [R32.1, §3.1–3.4; R32.4, §2.1–2.3].

[DERIVED] The specification therefore precedes the optimizer. If a false positive is defined as accepting an incorrect program, an increase in preferred-writing style does not repair it. If success is user preference under an explicitly subjective rubric, replacing disagreement with unit-test pass rate changes the target. The engineering artifact must make such changes reviewable rather than hiding them in a weighted sum.

## Intuition

[MATHEMATICALLY-DERIVED] An observation constrains only the variables to which its measurement procedure is sensitive. A test that executes one input leaves all other inputs unconstrained unless a theorem relates them. A pairwise label identifies an ordering for one comparison, not an absolute numerical utility. A trajectory-level success label can coexist with a wrong intermediate statement because later actions may repair it. Information is lost whenever a downstream consumer interprets a narrower measurement as a stronger claim.

[DERIVED] Separate four layers: the target property; the observation generated by a source; an estimator or decision procedure; and the scalar consumed by an update rule. The same human observation can train a ranking model or support a direct preference objective. The same deterministic checker can supply binary rewards or filter training examples. Those are different transformations of a feedback source, not different sources by virtue of their optimizer.

## Formulation

| Symbol | Local meaning | Domain |
|---|---|---|
| $u$ | Complete evaluation unit: prompt, candidate and any trajectory | Typed immutable record |
| $g(u)$ | Declared target property | Boolean or explicitly defined utility |
| $z$ | Feedback observation | Label, score, trace or certificate |
| $a$ | Producer identity, rubric and procedure version | Provenance tuple |
| $p_0$ | Prevalence of correct candidates in the evaluated population | $[0,1]$ |
| $s_v,f_v$ | Acceptance rates conditional on correct and incorrect candidates | $[0,1]$ |
| $k$ | Repeated observations per evaluation unit | Positive integer |
| $\rho$ | Equal within-unit correlation for the analytical example | $[0,1]$ |

[MATHEMATICALLY-DERIVED] For a binary acceptance channel, partition its accepted population by correctness. Bayes' rule gives

$$
\Pr(g=1\mid z=\mathrm{accept})=
\frac{p_0s_v}{p_0s_v+(1-p_0)f_v}.
$$
*(Eq. 32.1)*

The denominator must be positive; an empty accepted population has no defined precision. This calculation requires acceptance rates measured on the same population whose prevalence is supplied. It is invalid to import a sensitivity from one task family and a false-acceptance rate from an unrelated adversarial set without a transport argument.

[MATHEMATICALLY-DERIVED] If repeated scalar observations have common variance $v_z$ and equal pairwise correlation $\rho$, covariance expansion yields

$$
\operatorname{Var}(\bar z)=\frac{v_z}{k}\bigl[1+(k-1)\rho\bigr],\qquad
k_{\mathrm{eff}}=\frac{k}{1+(k-1)\rho}.
$$
*(Eq. 32.2)*

This is an accounting identity under equal moments, not a claim that model errors are exchangeable. More judgments need not add much independent evidence when the producer, rubric and candidate ambiguity are shared.

## Mechanism

[DERIVED] A human preference record contains the comparison set, randomized presentation order, annotation rubric, permitted tie/abstention values, annotator identifier or privacy-preserving grouping, and relevant context. Aggregation must preserve repeated judgments and the denominator used. Treat an abstention for insufficient expertise separately from a genuine tie between equally acceptable responses. Otherwise a downstream tie model learns annotator incapacity as indifference.

[DERIVED] AI feedback adds the exact judge model identifier, prompt, decoding configuration, tool access and parser. A generated explanation is an additional output of the judge; it is not independent confirmation of its verdict. To test presentation sensitivity, compare the original and swapped orders while mapping labels back to candidate identity. Retain both observations even if an aggregation rule refuses inconsistent cases. A consistency filter changes the retained population and must be reported alongside coverage.

[DERIVED] Deterministic verification records the executable predicate and its input domain. Determinism means repeated identical inputs produce the same result under fixed state; it says nothing about semantic completeness. Execution outcomes additionally preserve exit status, completed assertions, tool errors, timeout and resource exhaustion. A timeout is not a logically justified rejection of a mathematical theorem, and process termination is not proof that the requested assertions ran.

[DERIVED] Process labels require a state boundary: the prefix available to the annotator, whether future steps were visible, and whether the label means local validity, recoverability, expected final success or factual support. A label created with future outcomes can be useful supervision, but it cannot be represented as a causal online judgment without changing the information set. Environment returns aggregate externally defined per-transition values, discounting and terminal conditions. Their unit might be task score or a constructed utility; it is not inherently human preference.

[DERIVED] The transformation from typed observations to $R(x,y)$ is an explicit interface. A policy for rejected, abstained and infrastructure-failed records must be declared before optimization. Combining correctness and style as $R=w_c z_c+w_s z_s$ permits style to compensate for incorrectness whenever weights and ranges allow it. If correctness is non-negotiable, implement a feasibility predicate followed by ranking among feasible candidates. That change is a constrained objective, not merely a different choice of weights.

## Algorithm

[DERIVED] Algorithm 32.1 is the book's feedback-ingestion contract. It does not reproduce a particular lab's pipeline. Inputs are a finite record stream and frozen schema/rubric versions; outputs are admitted observations and a complete rejection ledger. No model weights are changed.

**Algorithm 32.1 — Typed admission with conserved identities.** Let $\mathcal U=(u_1,\ldots,u_n)$ be finite, $v$ the frozen schema/target/split bundle, $\mathcal D_i$ admitted records and $\mathcal Q_i$ quarantined records. The partial parser $P_v$ returns a tagged error instead of an observation on malformed input; $A_v$ checks identity, information boundary and split lineage.

$$
\begin{aligned}
(1)\;&(\mathcal D_0,\mathcal Q_0)\leftarrow(\varnothing,\varnothing).\\
(2)\;&i\leftarrow1,\ldots,n;\quad o_i\leftarrow P_v(u_i).\\
(3)\;&a_i\leftarrow \mathbf1[o_i\ne\mathrm{ERROR}\ \land\ A_v(o_i)].\\
(4)\;&\tilde o_i\leftarrow\operatorname{CanonicalIdentity}_v(o_i)\quad\text{if }a_i=1.\\
(5)\;&s_i\leftarrow\begin{cases}\mathrm{ERROR},&\text{incomplete execution},\\
\operatorname{TypedStatus}_v(\tilde o_i),&\text{otherwise},\end{cases}\quad(a_i=1).\\
(6)\;&\mathcal D_i\leftarrow\mathcal D_{i-1}\cup\{(u_i,\tilde o_i,s_i,v)\}\quad(a_i=1).\\
(7)\;&\mathcal Q_i\leftarrow\mathcal Q_{i-1}\cup\{(u_i,\operatorname{Reason}_v(o_i))\}\quad(a_i=0).\\
(8)\;&\text{leave the other ledger unchanged at each branch}.\\
(9)\;&\operatorname{IDs}(\mathcal D_n)\,\dot\cup\,\operatorname{IDs}(\mathcal Q_n)=\operatorname{IDs}(\mathcal U).\\
(10)\;&\text{return }(\mathcal D_n,\mathcal Q_n,\operatorname{Coverage}_v(\mathcal D_n)).
\end{aligned}
$$

The disjoint union is checked over unique ingestion-occurrence identities, assigned before line 1 while preserving the declared source IDs. All occurrences of a duplicated declared record ID fail $A_v$ and enter quarantine through line 7; they are not merged into one observation. This distinction conserves incoming records without counting repeated source identities as independent evidence. An admitted ERROR remains an observed execution status and is never converted into a passing semantic label.

[DERIVED] The invariant is conservation of input identities: every input has one terminal ingestion status and retains its original provenance. Unknown states are never promoted to acceptance. A finite stream ensures termination; per-record tool calls require separate finite timeouts. Hash checks establish artifact identity, not the truth of its content. The procedure distinguishes data validation from scientific validation.

## Implementation

[DERIVED] A source-neutral implementation uses tagged records rather than one permissive JSON score field. Its labels should retain both raw and canonical values so parser changes can be replayed. Candidate text is immutable; privacy transformations receive their own identity because redaction can alter what a judge can evaluate. Annotator or judge repetitions share a dependence-group key, allowing clustered uncertainty estimates instead of fictitious independent sample counts.

[DERIVED] In-memory batching can combine homogeneous input schemas, but each output must map back by stable identifier. Positional association alone fails when a worker retries or returns out of order. Retrying the same deterministic checker should be idempotent. Retrying a stochastic judge creates an additional sampled observation and increments its cost ledger. A deadline-expired response arriving later cannot overwrite an already adjudicated record without an explicit revision event.

[PAPER-REPORTED] VPR's implementation uses ROLL with vLLM and Megatron-LM. These are source-reported implementation choices, not a pinned reproduction here. vLLM is an Inference engine entry and Megatron-LM a Distributed training entry in the reference stack; ROLL is outside the listed systems and is identified only as the implementation named by the eligible primary paper. [R32.4, Appendix F].

[MATHEMATICALLY-DERIVED] For $n_u$ units, $k$ judge repeats and $t_j$ generated judge tokens per repeat, generated feedback volume is $n_uk t_j$. Token storage is linear in that volume before compression. A deterministic parser adds linear work in payload length; checker execution may dominate and needs its own complexity bound. Learned producer parameters, forward FLOPs, KV memory, communication and service latency belong to the producer boundary, whereas schema validation has no trainable parameters. Energy and money require measured joules and billing rates; they remain UNVERIFIED for this manuscript.

## Experimental design

[PAPER-REPORTED] IRPM forms chosen/rejected rollout groups and evaluates alternative intergroup signals; its experiment filters weak preference labels and long inputs before training. That selection is part of the empirical target, not a neutral serialization step. VPR studies three structured environments with distinct search-, constraint- and posterior-based oracles. Its reported normalization batches trajectories from different initial states rather than same-prompt response groups. These protocol details prevent treating their rewards as equivalent observations. [R32.1, §4.1; R32.4, §2.2 and Appendix F].

[DERIVED] The chapter's proposed specification audit, detailed in [verification](verification.md), holds candidates fixed while swapping only the feedback channel. Report agreement conditional on task family, admitted coverage, error and abstention rates, and cost per admitted record. A pooled agreement percentage without a source-by-target confusion ledger cannot identify whether disagreement is semantic, annotator-dependent or infrastructural. This audit has not been run.

## Observations

**What the paper claims.** [PAPER-REPORTED] The two cited methods make different source-to-reward transformations; neither supplies a universal interchangeability result. [R32.1, §3; R32.4, §2].

**What the evidence shows.** [DERIVED] Their documented protocols establish the identity of the constructed signal. They do not establish that a higher scalar means the same property across domains or source types.

**What we infer.** [MATHEMATICALLY-DERIVED] Eq. 32.1 permits accepted-set precision to fall after prevalence decreases, even with unchanged conditional checker behavior. Calibration must therefore be checked under the policy's current candidate distribution.

**What remains unknown.** [UNVERIFIED] Cross-source agreement on this book's artifact, dependence between judges and achieved execution cost await the proposed audit. No independent reproduction is claimed.

## Failure modes

[DERIVED] Symptoms include rising reward with falling assertion count, increasing parser rejection hidden by retry, order-dependent preferences, and unusually high agreement among judges sharing a template. Diagnose these separately. Infrastructure errors require harness repair; subjective disagreement requires a target or population decision; a false acceptance requires counterexamples to the predicate. Changing a threshold cannot resolve an undefined target.

## Siblings

[DERIVED] [Preference models](32-2-preference-models.md) change how comparative observations constrain latent utility; [verification](32-4-outcome-and-process-verification.md) changes the proposition a checker can establish. [Oversight](32-5-oversight-strategies.md) changes who validates the evidence and when. Each comparison is on evidential scope, rather than an unsupported ranking of feedback sources. A mixture retains each source's limitations and introduces an aggregation specification that must itself be audited.

## Extensions

[DERIVED] For tools and embodied actions, bind feedback to both intended command and observed transition. A successful API response can differ from a successful external effect. For multimodal candidates, preserve preprocessing and the sensory inputs actually visible to the evaluator; missing frames or crops restrict its information. These are contract consequences, not claims that any named deployment already implements them.

## Limitations

[DERIVED] A typed record prevents category confusion but does not make a rubric valid, a human impartial or a checker complete. The framework is falsified as an adequate specification when two consumers can legitimately give different interpretations to the same admitted record without violating its schema. Fix the missing semantic field before fitting another estimator.

## Reproducibility

[DERIVED] Preserve raw payloads, schema and rubric hashes, source identities, candidate lineage, split ownership, parsing rules, timeouts, aggregation weights and dependence groups. Recompute Eq. 32.1 from conditional counts and state the prevalence denominator. Reference versions and first-release dates appear in [references](references.md). Source experiments are reported evidence; the proposed ingestion audit is unexecuted.
