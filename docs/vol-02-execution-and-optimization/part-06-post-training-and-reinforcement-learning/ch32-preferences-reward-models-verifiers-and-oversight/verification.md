# Chapter 32 verification

[DERIVED] This document specifies the plan's artifact and falsifiable audit. It is a **proposal**, not an executed calibration, model-training, verifier-soundness or adversarial experiment. Reported source experiments remain in the six manuscript sections with claim-local citations. The artifact is intended to reveal discrepancies between reward, human preference and scoped correctness rather than declare one scalar a universal measure of quality.

## Verification task

**Question.** Does the declared reward/verification specification retain meaningful agreement with human judgment or scoped truth after a bounded optimizer deliberately selects high-reward responses?

**Hypothesis.** The frozen specification predicts comparison labels or checker-defined outcomes on its stated support, distinguishes ties/unknown/error, and reveals rather than conceals any selected-distribution disagreement.

**Setup.** [ASSUMED] For an executable pilot, choose 400 prompt-lineage units divided equally between structured-checkable and open-ended rubric tasks; reserve disjoint development, calibration and final audit units. Use 4, 16 and 64 candidate caps as separate exposure conditions, with total generated-token caps matched across alternative selectors. These are proposed design values, not properties of a source experiment. Increase the audit size if uncertainty is too wide; report that decision before evaluating the final holdout.

**Controls.** Freeze the base generator, tokenizer/serializer, task target and rubric. Compare one random candidate, a proxy-selected candidate and an equal-work alternate selector. Keep a random sample of rejected candidates. Order-swap pairwise comparisons; retain ties and abstentions; cluster by prompt lineage and annotator group. A deterministic checker supplies only its declared predicate. For open-ended labels, use blinded independent assessors with a recorded disagreement/adjudication process. Do not make human consensus a hidden assertion of objective truth.

**Interventions.** Build formatting/verbosity transformations only after validating that they preserve requested semantics and correctness. Include both correct and incorrect responses so a preferred style cannot stand in for truth. For integrity testing, use inert local fixtures that deliberately attempt an unauthorized score-state change; no production secrets, live attacks or real external targets are necessary. An independently owned evaluator verifies that the attempted change did not alter its artifact or result identities.

[DERIVED] Compare scalar, shared-head and independently trained reward estimators on identical input candidates and declared budgets. Separate shifts in candidate-generation checkpoints from random prompt-group holdouts. Report proper probability loss, ranking error, abstention coverage and accepted-task correctness separately; preference accuracy alone cannot test calibration or exploitation resistance. This comparison remains an unexecuted book protocol.

**Measurements.** Report pairwise accuracy with order consistency, ordinal NLL/category error where applicable, Brier score for probabilities, reliability bins and their support, accepted-set precision/coverage, false-acceptance and false-rejection conditional rates, abstention/error/timeout rates, member-error covariance, raw component scores and PGR. At every exposure condition show proxy and independently evaluated target curves with both selected and random denominators. Keep generated tokens, reward calls, checker invocations, tool actions, latency and hardware utilization distinct.

**Uncertainty.** Predeclare a prompt-cluster bootstrap or a justified model-based interval, and identify which component addresses annotator dependence. Use independent audit units rather than raw expanded pairs as sample size. Report per-slice denominators and missing labels. If multiple rules are evaluated, distinguish a fixed-family comparison from adaptive threshold search; Eq. 32.16 applies only under its stated fixed-rule independence premises. A held-out result used to choose a new method becomes development information for a later version.

**Expected failure signatures.** Increasing proxy reward with falling target outcome; unmodeled order bias; high confidence on unsupported domains; identical errors across reward ensemble members; hidden loss of coverage; unresolved checker timeouts mislabeled as success; a candidate or critic altering the score state; or a formatter changing the intended task rather than just presentation.

**Falsification.** Reject the proposed handoff if a score has no declared target interpretation, the optimizer can modify its final evaluator, a final audit influences candidate selection without a fresh holdout, or the report omits adverse units. If a supposedly sound checker accepts an intentionally invalid artifact inside its declared domain, reject that soundness claim immediately. A statistically unresolved target change is reported as unresolved, not promoted to an improvement.

## Acceptance criteria

[DERIVED] The following gates validate the proposed study's integrity. They do not certify universal reward quality or model safety.

| Gate | Criterion | Failure consequence |
|---|---|---|
| Identity conservation | Every input ID belongs to exactly one admitted/quarantined ledger; every candidate outcome retained | Reject pipeline accounting |
| Mathematical domain | Cutpoints strictly ordered; calibrated temperatures positive; calculator outputs finite; PGR denominator positive | Reject affected computation |
| Independent data roles | No prompt lineage crosses designated train/calibration/final-audit roles; final labels inaccessible to search | Reject independent-test interpretation |
| Scoped acceptance | ACCEPT implies all pinned assertions completed, unchanged target/candidate hashes and permitted checker dependencies | Reject verifier result if any condition absent |
| Dependence disclosure | Group IDs, repeat reuse and ensemble member dependence documented | No IID precision claim without justification |
| Calibration reporting | Metric formula, support, bins, uncertainty and shift slices present; ties not silently discarded | Reject incomplete report; do not invent a universal ECE cutoff |
| Optimization audit | Random/selected/alternate outcomes and matched-work denominators retained for each cap | Reject reward-improvement claim without target/work context |
| Oversight integrity | Role permissions and query caps enforced; final evaluator owns authoritative score path | Reject authority boundary if bypassed |
| Empirical interpretation | Benefit requires independently adjudicated target evidence with predeclared uncertainty; null/negative findings retained | Retain uncertainty or report degradation |

[DERIVED] Equation checks include the BT integral under equal-scale independent noise; listwise suffix normalization; nonnegative telescoping ordinal probabilities; translation invariance and disconnected graph gauges; monotonic derivatives of the ranking loss; calibrated-probability interpretation; equal-correlation ensemble variance; the union bound without independence; conditional oversight failure; PGR denominator sensitivity; finite-family versus adaptive audit; finite-set proxy regret; IID rare-exposure probability; and bounded-utility total-variation transport. Counterexamples to stronger claims are part of the mathematical review, not empirical results.
